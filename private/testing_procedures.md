# Premium Reading Testing Procedures

This document describes how to test premium AI readings while keeping production access controlled.

## Current State

- The app uses RevenueCat on the client to determine whether premium features are enabled.
- The premium reading API currently calls OpenAI from the server.
- Server-side RevenueCat entitlement verification is planned but not implemented yet.
- Until server-side verification is implemented, treat the premium reading endpoint as sensitive and avoid exposing test bypasses publicly.

## Preferred Testing Path

Use real RevenueCat sandbox/test entitlements whenever possible.

1. Configure the RevenueCat Android public API key for the app environment.
2. Use a sandbox/test purchase account.
3. Confirm the app reports the `premium` entitlement as active.
4. Cast a reading from the app.
5. Confirm the app reaches the Premium Reading screen.
6. Confirm the premium reading API returns a generated reading.
7. Confirm the reading is saved in local history.

This path tests the real paywall, restore flow, entitlement check, app routing, premium reading request, OpenAI call, and local reading storage.

## Planned Server-Side Testing Path

After server-side RevenueCat verification is implemented:

1. Set the server-only `REVENUECAT_SECRET_API_KEY` in the Netlify environment.
2. Set the expected entitlement ID, usually `premium`.
3. Use a RevenueCat sandbox/test customer with the active premium entitlement.
4. Have the app send the required authenticated user/customer identifier with the premium reading request.
5. Confirm the server verifies the entitlement before calling OpenAI.
6. Confirm non-premium users receive a `403` or equivalent "premium required" response.
7. Confirm invalid or missing authentication receives a `401` or equivalent "authentication required" response.

## Mock OpenAI Testing

Add and use mock mode for UI and flow testing that should not spend OpenAI credits.

Recommended environment variable:

```txt
AI_READING_MOCK_RESPONSE=true
```

Expected behavior:

- Premium reading requests return a canned response.
- No OpenAI API call is made.
- Entitlement checks should still run unless testing a specific entitlement bypass.
- The returned response should look structurally identical to a real premium reading response.

Enable mock mode:

1. Set `AI_READING_MOCK_RESPONSE=true` in the relevant Netlify/dev environment.
2. Redeploy or restart the local serverless/dev process.
3. Run the premium reading flow from the app.
4. Confirm the response clearly indicates it is a mock/test reading.

Disable mock mode:

1. Remove `AI_READING_MOCK_RESPONSE` or set it to `false`.
2. Redeploy or restart the local serverless/dev process.
3. Run one controlled premium reading test.
4. Confirm the response is generated by OpenAI.

## Test Bypass Access

Use bypass access only when RevenueCat sandbox testing is not practical.

Recommended environment variables:

```txt
ALLOW_AI_READING_TEST_ACCESS=true
AI_READING_TEST_BYPASS_TOKEN=<server-only-random-token>
```

Rules:

- Never put bypass tokens in `EXPO_PUBLIC_*` variables.
- Never hard-code bypass tokens in app code.
- Never commit bypass tokens to git.
- Prefer enabling bypass only in local, preview, or review environments.
- Keep bypass disabled in production unless there is a deliberate emergency/testing reason.

Enable bypass access:

1. Generate a long random token.
2. Set `ALLOW_AI_READING_TEST_ACCESS=true` on the server.
3. Set `AI_READING_TEST_BYPASS_TOKEN` on the server.
4. Redeploy or restart the server.
5. Send the bypass token in the agreed test header.
6. Confirm test access works.
7. Confirm requests without the token still fail.

Disable bypass access:

1. Remove `AI_READING_TEST_BYPASS_TOKEN`.
2. Set `ALLOW_AI_READING_TEST_ACCESS=false` or remove it.
3. Redeploy or restart the server.
4. Confirm bypass-token requests are rejected.
5. Rotate the token if it was shared outside a trusted testing context.

## Emergency Disable Procedure

Add a global kill switch for premium AI readings.

Recommended environment variable:

```txt
AI_READING_ENABLED=false
```

Expected behavior:

- The premium reading API returns a friendly unavailable/error response.
- No RevenueCat API call is required.
- No OpenAI API call is made.
- The app should show a retryable/unavailable message.

Disable premium AI readings:

1. Set `AI_READING_ENABLED=false` in Netlify.
2. Redeploy or restart the function environment if required.
3. Confirm `/api/premium-reading` no longer calls OpenAI.
4. Check OpenAI usage to confirm requests have stopped.

Re-enable premium AI readings:

1. Remove `AI_READING_ENABLED` or set it to `true`.
2. Redeploy or restart the function environment if required.
3. Run one controlled premium entitlement test.
4. Confirm request logs and OpenAI usage look normal.

## Production Preflight Checklist

- [ ] RevenueCat client public key is configured for the build.
- [ ] RevenueCat entitlement ID matches the dashboard entitlement.
- [ ] Server-side RevenueCat secret key is configured.
- [ ] Server verifies entitlement before OpenAI calls.
- [ ] Server-side per-user premium reading limits are enabled.
- [ ] IP rate limiting remains enabled.
- [ ] OpenAI key is dedicated to this app.
- [ ] OpenAI auto recharge is disabled unless intentionally enabled.
- [ ] OpenAI usage/budget limits are configured where available.
- [ ] Mock mode is disabled.
- [ ] Test bypass is disabled.
- [ ] Global kill switch is enabled only if intentionally taking readings offline.

## Post-Test Cleanup

After any testing session:

1. Disable mock mode unless it is intentionally needed for a review environment.
2. Disable bypass access.
3. Rotate any bypass token that was shared.
4. Check Netlify logs for unexpected request volume.
5. Check OpenAI usage for unexpected spend.
6. Confirm production environment variables do not contain test-only settings.
